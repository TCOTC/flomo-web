## 现在拖一张带图的卡，实际发生了什么

1. 注入脚本在 `dragstart` 里扫正文 `img` 和卡片 `.files` 里的 `img`，把 `src` 原样写进 HTML，例如 `<p><img src="https://....jpg"></p>`。
2. 思源 `paste` 总线拿到这份 HTML，用 Lute 转成块插进文档。
3. 文档里的图仍指向 flomo / OSS 的远程地址。思源内核之后如果去下载，走的是**内核自己的网络**，没有 webview 里那份登录 cookie。

所以不是「没把图拖过去」，而是「只拖了网址」。这个网址谁能打开，图就亮；要登录才能下，图就裂。

`src` 还有两个边角：相对路径没拼成绝对地址；懒加载图如果还是空 `src` / 只在 `data-src`，拖的时候等于没图。

---

## 第 3 条四个方案差在哪

| 方案 | 谁去拿文件 | 要不要登录 cookie | 拖的时候卡不卡 | 结果 |
| --- | --- | --- | --- | --- |
| A | 思源内核按 URL 下载 | 不要，也拿不到 | 不卡 | 公开 URL 能转成 `assets/`；要登录的图仍裂 |
| B | 先在 flomo 网页里读字节，再交给思源上传 | 要，网页里本来就有 | 见下面 | 登录才能看的图也能进 `assets/` |
| C | 谁都不拿 | — | 不卡 | 文档里永远是远程 URL，裂了就算了 |
| D | 暂不转存，只把 `src` 拼成 http(s) 绝对地址 | 同现在 | 不卡 | 少裂「相对路径」这一种，登录墙还在 |

A 和 B 的目标一样：最后都是思源资源文件。差别只是**谁有资格把字节读下来**。

## 方案 B 具体怎么「读图片」

B 不是截屏，也不是让思源去翻 webview 的磁盘。就是：图片已经显示在 flomo 网页里了，这段网页跑在独立的 Electron guest 里，guest 带登录态，可以像普通网页一样 `fetch` 这张图，拿到文件字节，再交给宿主（思源插件）去做 `/api/asset/upload` 之类的上传。

读的时机有限制：**浏览器规定 `dragstart` 必须同步写完 `dataTransfer`**，里面不能 `await fetch`。所以 B 不能写成「开始拖的那一毫秒再去下载」。

能落地的只有两种时机：

### B1. 放下之后再读（比较实际）

1. 拖的时候仍然只带 URL 和标记，跟现在一样，不卡。
2. 卡片已经丢进编辑器后，插件拿着这些 URL，对**同一个** webview 调 `executeJavaScript`。
3. 网页里执行 `fetch(图片地址, {credentials: "include"})`，把结果变成 base64 / ArrayBuffer 返回宿主。
4. 宿主上传成思源资源，再把块里的 `src` 换成 `assets/...`。

用户会先看到远程图（或裂图占位），过一小会儿变成本地资源。实现要处理：webview 已经关了、用户拖得很快连拖几张、上传失败时要不要回退。

**已选 B1。**

### B2. 卡片出现时就先读进内存

卡片一渲染就开始 `fetch`，拖的时候内存里已经有 data URL。`dragstart` 仍然是同步的，所以这能满足浏览器限制。

代价是列表一长就预下载大量图，费流量、费内存，滚动时还要管失效。一般不值得。

### 为什么不能「拖的那一下读完再放下」

`dragstart` 处理函数一返回，剪贴板数据就定了。`fetch` 是异步的，等它回来时这次拖拽已经结束。没有合法的「拖住不放、等图下完」API。

## 怎么判断 A 够不够

看你现在拖**带图**的卡片，进思源之后图是哪种：

- 一直正常 → 多半是公开 OSS 地址，**A 或甚至 C 都行**；A 只是再存一份到 `assets/`，以后 flomo 删图也不裂。
- 必裂 / 过一会儿裂 → URL 带鉴权或过期参数，**要 B** 才能稳定。
- 没试过 / 不确定 → 拖一张带图的卡看一下即可，不必先做 B。

A 的实现位置也和现在不同：现在 `paste` 只 `HTML2BlockDOM`，没有让内核去转存。选 A 等于在转块之后再走一层「按 URL 拉文件、改 src」。选 C 就是维持远程 URL，什么都不加。

## 第 4 条：网页版有录音

编辑器上传控件仍是 `accept=".jpg,.png,.jpeg,.gif,.webp"`（网页里不能新录）。但 App 录的音会显示在网页卡片上。样本结构（OSS 签名已打码）：

```html
<div class="memo normal" data-slug="…">
  <div class="richText"><p>你好。</p></div>
  <div class="files">
    <div class="audio-player">
      <audio src="https://flomo.oss-cn-shanghai.aliyuncs.com/file/…/….m4a?OSSAccessKeyId=…&Expires=…&Signature=…"></audio>
    </div>
  </div>
</div>
```

要点：

- 文件在 `.files .audio-player audio` 的 `src`，不是 `img`。现在的 `getFileImages` 扫不到，拖完录音会消失。
- 地址是阿里云 OSS **预签名 URL**（`Expires` + `Signature`）。过期后，贴在思源里的这条链接会 403。所以「只贴原链接」不稳。
- 过期前没有 cookie 也能下（密钥在 query 里）。B1 仍然值得做：本地 `assets/` 不受过期影响。读的方式和图相同：放下后 webview `fetch(audio.src)` → 上传。
- 还没见到 PDF / 其它文件的 DOM。若以后出现，可以和录音走同一条「非图片附件」路径。

进思源之后可以长成四种：

| 方案 | 拖完立刻怎样 | 过期之后 | 和 B1 的关系 |
| --- | --- | --- | --- |
| A. 丢掉，提示「已忽略录音」 | 正文在，没音频 | — | 不必读字节 |
| B. 插一条指向 OSS 的链接 / `<audio src=远程>` | 当时能播 | 链接失效 | 不必读字节 |
| C. 和图片一样 B1：读字节、上传、换成思源音频 | 先远程、再变本地 | 还能播 | 和图共用一条管道 |
| D. 静默丢掉 | 正文在，没音频，也没提示 | — | 不必读字节 |

C 和图片管道重合最多：拖的 HTML 先带上 `<audio src="原地址">`，paste 之后同一轮把图和 `.m4a` 一起拉下来上传，再改 `src`。

---

## 第 4 条决议：C

和图片共用 B1：拖的 HTML 先带 `<audio src="原地址">`，paste 之后同一轮把图和 `.m4a` 一起拉下来上传，再改 `src`。PDF / 其它文件若以后出现，走同一条「非图片附件」路径。
